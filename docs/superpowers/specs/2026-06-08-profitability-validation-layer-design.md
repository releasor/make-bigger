# 赚钱能力验证层设计

日期：2026-06-08

## 目标

把当前 A 股虚拟交易平台升级为“实盘前能力验证系统”：系统不承诺自动赚钱，但要能用历史数据、虚拟盘和风险指标判断一个策略是否值得继续运行、是否应该降低权重、是否应该暂停，以及是否有资格进入未来的人工确认交易模式。

本阶段的核心产出不是实盘下单，而是三个能力：

- 回测与参数优化：用历史 K 线评估策略表现，并扫描参数组合。
- 交易质量评分：给每条买入信号计算胜率倾向、风险收益比、止损距离和综合评分。
- 虚拟盘晋级安全门：只有持续满足指标阈值的策略，才显示“可进入人工确认交易观察”的状态。

## 非目标

本阶段不做：

- 真实券商连接。
- 真实资金托管。
- 自动真实下单。
- 承诺收益或稳赚。
- 绕过用户确认的实盘交易。
- 高频交易基础设施。

## 合规与安全边界

系统必须持续区分虚拟盘、人工确认交易和未来实盘交易。当前阶段只实现虚拟研究能力。

设计参考的现实边界：

- 中国证监会发布的《证券市场程序化交易管理规定（试行）》自 2024-10-08 起实施，明确程序化交易是通过计算机程序自动生成或者下达交易指令，并要求不得影响交易所系统安全或扰乱正常交易秩序。
- 上海证券交易所《程序化交易管理实施细则》自 2025-07-07 起施行，要求程序化交易投资者进行报告管理，并要求技术系统具备验资验券、权限控制、阈值管理、异常监测、错误处理、快速撤销申报、暂停申报和系统隔离等风控功能。
- 深圳证券交易所《程序化交易管理实施细则》自 2025-07-07 起施行，作为未来深市程序化交易适配时的规则边界。

参考链接：

- 中国证监会公告：《证券市场程序化交易管理规定（试行）》：https://www.csrc.gov.cn/csrc/c101954/c7480579/content.shtml
- 中国证监会发布说明：https://www.csrc.gov.cn/csrc/c100028/c7480577/content.shtml
- 上海证券交易所《程序化交易管理实施细则》：https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml
- 深圳证券交易所《程序化交易管理实施细则》发布通知：https://www.szse.cn/lawrules/rule/allrules/bussiness/t20250403_612770.html

因此，本阶段新增的“晋级安全门”只能表达研究状态，不能表达“允许自动实盘”。未来进入真实交易前，必须另行实现券商适配器、报告信息记录、异常交易监控、交易暂停、撤单、应急处置和人工授权流程。

## 用户体验

Web 控制台新增一个“赚钱能力验证”区域，位置在短线信号中心之后、日报指标之前。

该区域展示：

- 当前策略的回测总览：总收益、最大回撤、胜率、盈亏比、夏普、交易次数。
- 参数优化结果：最佳参数、候选参数排行、是否疑似过拟合。
- 信号质量评分：最新短线买入信号的综合评分、预期收益、最大风险、风险收益比和是否允许提示买入。
- 虚拟盘晋级状态：观察中、可继续虚拟盘、暂停优化、可进入人工确认交易观察。

界面文案必须避免“稳赚”“自动赚钱”等承诺性表达，使用“通过验证”“未通过验证”“继续观察”“暂停运行”等工程化状态。

## 回测模型

回测输入：

- 策略定义。
- 历史行情数据。
- 初始资金。
- 参数组合。
- 手续费、印花税、滑点。
- 最大单票仓位。
- 最大组合回撤阈值。

回测输出：

- `totalReturnPct`：总收益率。
- `annualizedReturnPct`：年化收益率，样例数据不足时可以为 0。
- `maxDrawdownPct`：最大回撤。
- `winRate`：盈利平仓交易数 / 已平仓交易数。
- `profitLossRatio`：平均盈利 / 平均亏损的绝对值。
- `sharpeRatio`：日收益均值 / 标准差，样例数据不足时可以为 0。
- `tradeCount`：已平仓交易数。
- `score`：综合评分。
- `qualified`：是否达到策略验证阈值。

综合评分采用可解释公式：

```text
score =
  收益得分 * 0.30 +
  回撤控制得分 * 0.25 +
  胜率得分 * 0.20 +
  盈亏比得分 * 0.15 +
  交易样本得分 * 0.10
```

所有得分归一化为 0-100。综合评分达到 70，且最大回撤不超过配置阈值，且交易次数达到最低样本量时，策略才算通过回测验证。

## 参数优化

参数优化只扫描小范围、可解释参数，不做黑箱大规模搜索。

第一版扫描：

- `maxPositionPct`：0.05、0.10、0.15。
- `stopLossPct`：0.05、0.08、0.10。
- `buyThreshold`：1、2。

优化输出：

- 最佳参数。
- 排名前 5 的参数候选。
- 每组候选的回测指标。
- 过拟合提示。

过拟合提示规则：

- 最佳候选收益明显高于中位候选，但交易次数低于最低样本量，标记为“样本不足”。
- 最佳候选收益为正，但最大回撤超过阈值，标记为“回撤过高”。
- 最佳候选只依赖一个交易样本盈利，标记为“偶然性过高”。

第一版只给出提示，不自动替用户发布参数。

## 交易质量评分

交易质量评分面向单条买入信号。它不直接决定真实交易，只决定是否显示“高质量买入提示”。

输入：

- 短线买入信号。
- 近一段历史回测摘要。
- 当前止损价。
- 当前价。
- 历史同类信号命中率。

输出：

- `qualityScore`：0-100。
- `expectedReturnPct`：预期收益。
- `maxRiskPct`：从现价到止损价的最大风险。
- `riskRewardRatio`：预期收益 / 最大风险。
- `historicalWinRate`：同类信号历史胜率。
- `allowedToPromptBuy`：是否允许展示买入提示。
- `rejectionReasons`：不允许提示时的原因。

允许展示买入提示的最低条件：

- `qualityScore >= 75`。
- `riskRewardRatio >= 1.5`。
- `historicalWinRate >= 0.5`。
- `maxRiskPct <= 0.08`。

若不满足条件，页面仍可展示“观察信号”，但不能展示“特别值得关注”买入提示。

## 虚拟盘晋级安全门

系统维护策略验证状态：

- `needs_backtest`：缺少回测。
- `backtest_failed`：回测未达标。
- `paper_trading`：可继续虚拟盘观察。
- `paper_trading_failed`：虚拟盘近期表现未达标，建议暂停。
- `ready_for_manual_review`：可进入人工确认交易观察。

进入 `ready_for_manual_review` 的条件：

- 最近一次参数优化存在合格候选。
- 最近一次回测综合评分不低于 70。
- 最近 5 个虚拟交易日中至少 3 日达标。
- 最近 5 个虚拟交易日最大回撤不超过配置阈值。
- 没有未处理的数据质量警告。

该状态只表示研究系统建议人工复核，不表示自动实盘许可。

## 架构

新增能力仍放在 TypeScript monorepo 内，沿用现有边界。

`packages/domain`

- 新增回测结果、参数候选、信号质量评分、策略验证状态类型。

`packages/engine`

- 新增 `backtesting.ts`：运行历史回测和计算绩效指标。
- 新增 `parameterOptimization.ts`：扫描参数候选并排序。
- 新增 `signalQuality.ts`：计算单条信号质量评分。
- 新增 `strategyQualification.ts`：计算策略晋级状态。

`apps/api`

- 新增回测、优化、信号质量和验证状态接口。
- 继续使用内存状态。
- 不新增真实交易接口。

`apps/web`

- 新增“赚钱能力验证”区域。
- 展示回测、优化、信号评分和晋级状态。
- 对不合格状态给出暂停或继续观察提示。

## API

新增接口：

```text
POST /api/research/backtest
GET /api/research/backtest/latest
POST /api/research/optimize
GET /api/research/optimization/latest
GET /api/research/signal-quality
GET /api/research/qualification
```

接口返回中文 UI 所需字段，但内部类型使用英文键名。

`POST /api/research/backtest` 运行默认策略的样例历史回测。

`POST /api/research/optimize` 扫描默认参数网格。

`GET /api/research/signal-quality` 对当前短线信号进行质量评分。

`GET /api/research/qualification` 返回策略验证状态和进入下一阶段的缺口。

## 测试策略

按 TDD 实现。

核心测试：

- 回测能计算总收益、最大回撤、胜率、盈亏比和综合评分。
- 回撤超过阈值时，策略不合格。
- 参数优化能返回排序后的候选参数。
- 样本不足的最佳候选会标记过拟合提示。
- 信号质量评分低于阈值时，不允许展示买入提示。
- 信号质量评分达标时，允许展示高质量买入提示。
- 晋级安全门在缺少回测、回测失败、虚拟盘失败、全部达标时返回不同状态。
- API 能返回最新回测、优化、信号质量和验证状态。
- Web 能展示赚钱能力验证区域和不合格原因。

## 验收标准

完成后应满足：

- 用户可以在页面点击运行回测。
- 用户可以在页面点击参数优化。
- 页面展示最佳参数和候选参数排行。
- 页面展示策略是否通过回测验证。
- 页面展示每条短线信号是否通过交易质量评分。
- 页面展示策略当前是否只适合虚拟盘、是否建议暂停、是否可进入人工确认交易观察。
- 所有状态都明确标注“虚拟研究，不代表真实投资建议”。
- `npm.cmd run test`、`npm.cmd run typecheck`、`npm.cmd run build` 通过。
